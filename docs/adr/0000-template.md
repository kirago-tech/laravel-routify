# ADR-XXXX — Titre court de la décision

**Statut** : Proposé · Accepté · Déprécié · Remplacé par ADR-YYYY
**Date** : YYYY-MM-DD

## Contexte

Quel problème résolvons-nous ? Quelles forces sont en présence — techniques,
contraintes Laravel, contraintes d'équipe, dette existante ? Décrire les
faits observables, pas encore la solution.

## Décision

Quelle décision est prise ? Formulée à la voix active : *« Nous utilisons X
parce que Y. »* Exposer aussi le **comment** (un extrait de code ou un
schéma rapide vaut mieux qu'une longue paraphrase).

## Alternatives envisagées

Lister brièvement les options qui ont été considérées et pourquoi elles ont
été écartées. Cette section est ce qui distingue un ADR d'un commentaire de
code : on mémorise *les chemins non pris*.

## Conséquences

Les effets — positifs (✅), négatifs (⚠️), neutres (📝) — qui découlent de
la décision. Inclure les coûts récurrents que cette décision impose, les
nouvelles contraintes pour les contributeurs, et les ouvertures qu'elle
permet.
